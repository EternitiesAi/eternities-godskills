# Three bounded consumer applications

The fixtures and acceptance criteria were frozen before execution. Each worker
received only its assigned fixture, not the acceptance file or another consumer's
output. The acceptance file is published here afterwards for reproducibility.
These are synthetic tasks completed by real non-author agents using selected
methods. They are not raw/pack matched trials, fresh-context experiments, human
acceptance or live business/deployment outcomes. The company job intentionally
also exercises retained methods: good existing guidance need not be rewritten.

## Accepted outputs

The parent read each complete decision/assessment, the recovery reducer and
the proposed study. Acceptance is distinct from the consumers' own local checks.

- **Company:** the cash ladder closes at 28,000 / 18,000 / 6,000 / 14,000 with
  reserve gaps 0 / 0 / 9,000 / 1,000. The unsigned sale stays out of the base;
  reserve is a threshold, not a second payment. Campaign and annual prepayment
  worsen liquidity. The smaller bridge is conditional, still leaves a gap and
  does not prove continuous solvency. Replacement access preservation remains
  unknown. Routine support work stays inside existing authority and contract
  exceptions remain separate. No refund, commitment or migration was executed.
  The consumer caught and corrected its initial campaign arithmetic error;
  the failed check is preserved instead of claiming first-pass perfection.
- **Recovery:** all production requests reject scope and every paused state
  starts no work. Resume with unknown deployment requests lookup of
  `stage-R2-7`; a running operation is observed, never duplicated. Reliable
  absence permits one staging intent, except an unresolved failed smoke is
  held for repair rather than ignored. Successful deployment plus passing
  release-bound smoke is required to complete. The reducer contains no I/O.
  Its handoff retains the running worker, unrelated experiment, pause, stale
  checkpoint conflict and unit-test/deployment distinction. Exactly-once
  dispatch requires a real executor; the pure reducer does not claim it.
- **Evaluation:** the assessment preserves selection, model, prompt and scorer
  confounds; overlap and missing case IDs prevent a corrected win rate. Thirty
  percent fewer reported input tokens is not measured billing/cache savings.
  Tests and installation are not effectiveness proof. The proposed finite
  study specifies matched conditions, task identities, independent blinded
  scoring, retained timeouts/failures, cost accounting and a bounded adoption
  decision. The study is explicitly not executed.

`parent-checks.mjs` independently recalculates the four cash rows, checks all 80
valid reducer states plus malformed inputs, validates study structure and binds
the methods actually read. It does not automate the semantic judgments above.
Run it from any copy retaining this repository layout with Node 24+.

These three successful applications show useful outputs under these fixtures.
There is no unguided comparison, so they do not establish that Godskills caused
an improvement or that every skill is qualified on unseen tasks.

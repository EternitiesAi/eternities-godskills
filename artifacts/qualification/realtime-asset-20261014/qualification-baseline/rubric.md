# Frozen rubric and application rules

This rubric is frozen with the literal scenarios and manual oracle before the baseline response and before any candidate exposure. It evaluates the bounded written response, not asset quality in reality. The same author creates and applies it, so its result is a transparent self-assessment rather than independent certification or a blinded comparison.

## Two status layers

For a scenario acceptance gate:

- PASS: supplied observations support that specific declared gate, with its evidence scope stated. Reported closure, counts or size can pass their own fictional report gate without proving actual loading, rendering, residency or rights.
- FAIL: a supplied observation contradicts a declared requirement or threshold. An overall HOLD does not replace the reason and does not erase the conflict.
- UNKNOWN: applicable evidence, implementation mechanism or identity is missing. State the missing evidence and the bounded next check/decision. Never treat unperformed checks as PASS or infer a new measured failure.

Applicability is separate. A feature absent from the requested target has no gate result; record the exclusion and reason. A required mechanism absent from an implementation is a gap, not an applicability exclusion.

For each written-response criterion below:

- PASS: the response makes every consequential decision named in the row, ties it to supplied observations, preserves the specified limits and does not make a contradictory claim elsewhere.
- FAIL: the response makes a wrong acceptance decision, omits a consequential known blocker, treats a required unknown as accepted, substitutes evidence layers, invents a mandatory absent feature, or performs/claims an excluded action. Omission is FAIL, not UNKNOWN.
- UNKNOWN: the response attempts the required decision but its scope or evidence is too ambiguous to judge from the written record. Name the ambiguity; do not silently give credit. An overall response qualifies only when all applicable response rows pass and no cross-case invariant fails. This is a local written-record condition, not certification of a method.

No numerical score, superiority metric or broad pass-rate is authorized. Evaluate each of the two cases once against the frozen oracle. Do not revise the cases or rubric to accommodate the response.

| Criterion | Required observable behavior |

| RX2 Source/application honesty | Apply only the current three canonical guidance files. Distinguish explicit instructions from ordinary inference using supplied facts and from missing asset-specific guidance. Record the corrected methods path and do not imply commit verification. |
| RX3 Scope | Exactly two cases; no candidate exposure or comparison; no harness, implementation, source execution, network, providers, git mutation or subagents. |
| RX4 Freeze fidelity | Literal scenarios, manual oracle, rubric and canonical-source receipt have unchanged SHA-256 hashes after baseline drafting. Preserve the freeze-before-application order and report discrepancies instead of repairing the frozen text. |

## Fixed application protocol

1. Write these two literal scenarios, manual expected decisions, rubric and canonical source receipt.
2. Hash those five files; record the byte hashes and an observed UTC timestamp in a freeze manifest. Write that manifest before drafting baseline responses.
3. Apply the current guidance to the frozen scenarios without changing their premises. The oracle is available to the author; do not claim a blind baseline. Do not introduce a new asset-intake method as if it were already canonical.
4. Record baseline decisions, exact guidance connections, candid missing instructions and written-response rubric results. Recheck frozen bytes and canonical source bytes.
5. Return exact evidence files and hashes; stop. Candidate application belongs to a later separately labeled, newly authorized stage using these frozen inputs.

# Oracle method cards

## Local path

List the exact files or records in scope, revision or date, locator, and claims to settle. Inspect implementation reality before summaries. Use bounded excerpts and preserve contradictory evidence. A local result is current only within its observed revision.

## Authoritative path

Declare the freshness cutoff and source standard. For each current claim, record publisher, URL or document identity, revision or publication date, retrieval date, bounded supporting region, and refresh condition. If live retrieval is unavailable, keep the claim deferred.

## Hybrid reconciliation

Build local and authoritative ledgers separately. Match claims by identity, scope, version, and time; classify agreement, local drift, external drift, conflict, and missing coverage. Choose an authority basis for any conclusion and state what evidence would reverse it.

## Negative and comparative work

Before searching, set the retrieval floor, independent routes, corpus boundary, baseline, matched conditions, and stop rule. The strongest bounded negative conclusion is not-yet-refuted or inconclusive, never proof of absence, novelty, or universal coverage.

## Artifact-role evidence (DRAFT)

**Content revision: v2.** The method remains DRAFT. Use only when the question asks who authored, reviewed, approved, or materially challenged a particular artifact. Ordinary retrieval and summary stay on the local, authoritative, or hybrid path above. This card does not discover connectors or grant access to another person's records. It does not create a connector, grant private-source access, or confer copy, retention, or reuse rights. It does not change trigger, search, or routing behavior; those remain separate product decisions.

1. Fix the requested organization or product, artifact kind, version or effective date, and authorized source boundary. Record one stable artifact identity and a locator for why it is the requested target. A familiar name or newer off-target document is not a substitute.
2. Keep superseded versions visible when they explain disagreement. Select the version that answers the *dated question*, not merely the newest file. If several versions remain plausible and no date or version was specified, compare their role evidence and ask which version is meant rather than silently choosing one.
3. Bind every author, reviewer, or approver claim to the exact selected artifact/version and an attributed act or role-bearing designation for that same target. A byline on the selected artifact/version supports authorship only for that version. For a formal approver claim, require a completed approval act attributed to the person whose object is the exact selected artifact/version. Match the actor, action, object, and version; if the approval record does not identify that object/version, leave the formal approver unverified. Approval of access to inspect the artifact is a different act and is not artifact approval. Approval of a request to create or change it is a different act and is not artifact approval. Approval to distribute it is a different act and is not artifact approval. A substantive attributed challenge or requested change supports participation in review, but does not by itself prove appointment as the formal reviewer. A formal reviewer designation requires a role-bearing record tied to the same artifact/version. A review invitation, attendance list, mention, or edit permission alone supports only association.
   Apply the same target-bound object test to direct and paraphrased questions: “Who approved the report?” and “Who gave final sign-off on version 3?” are wording variants, not proof of which object was approved.
4. Separate observed act from role inference. When only participation is evidenced, say that the reviewer or approver is unverified and name the missing trail. A secondary summary that repeats a role label is not a substitute for the underlying act.
5. Return the target/version decision, a role table with exact locators and observed acts, rejected near-matches, access limits, and the smallest follow-up evidence that could change the answer. Do not reveal people or material beyond the requester's access.

Contrast checks: if a newer report is for another product, reject it for a historical target-specific question even if the same person appears. If a meeting lists three attendees but contains no attributed review, report participants and **no confirmed reviewer**. Neither a filled table nor an offline prompt fixture proves any real person's role or a search system's recall; inspect the permitted artifacts and review trail for the actual case.

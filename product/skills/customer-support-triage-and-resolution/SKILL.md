# Customer support triage and resolution

Use for an incoming support issue, a support queue pattern, an investigation
handoff or closing the loop after a fix. Use ordinary competence for a simple
acknowledgment. Account-health strategy belongs to Agora; code repair to the
engineering owner; actual security incidents to the authorized defensive process.

## Working method

1. Recover the customer's actual problem, environment, start time, blocked work,
   affected scope and observations. Distinguish reported symptoms, reproducible
   behavior and an unconfirmed cause. Ask only for the missing fact that changes
   the next action, and never request passwords or unnecessary private data.
2. Assess impact, urgency, scope, reversibility and available workaround. Apply
   a supplied severity/SLA policy when valid; otherwise state a provisional
   risk assessment. Do not invent response deadlines, root cause or a fix date.
3. Search authorized known issues and prior cases when useful. Similar symptoms
   are a possible cluster, not proof of one cause. Keep each customer's distinct
   evidence and privacy boundary when linking cases.
4. Perform already-authorized safe troubleshooting, documentation or local fixes.
   Choose a reversible discriminating check and record its actual result. Changes
   to accounts, billing, access or production require their matching authority.
5. Resolve at the support level when the evidence and safe action suffice;
   otherwise create a focused handoff with attempted checks, impact, exact
   evidence, unresolved question, requested action and receiving owner.
6. Draft or send the authorized customer update in plain language. Distinguish
   confirmed facts, investigation, workaround and next agreed checkpoint. Report
   only messages, escalations or fixes actually performed.
7. Verify resolution against the original failure and target environment, then
   confirm the customer's outcome when available. If no confirmation exists,
   retain that separate state instead of silently declaring customer success.

Use [methods.md](references/methods.md) for triage, duplicate handling and closure.
Deliver a useful response and case/handoff record, not a generic checklist.
Continue authorized work through its next safe action; a draft is not a sent reply.

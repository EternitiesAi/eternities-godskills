# October 2 conditional-method discovery contract

This is the parent's new product intent, not a candidate approval. It supersedes
neither a failed review nor the source ledger. The two failed package experiments
remain failed and unmerged: Hermes v2 and Math v4 tried broad owner-level search
keywords that captured adjacent owners. The earlier positive top-1 discovery
contract is **abandoned, not passed**. Its original criteria and negative evidence
remain in their original versioned artifacts.

## Useful content without search regressions

Base this new candidate on the reviewed portable core release
`2260b471f889f5c25b772fc50d4e83566fe8a4ef28a7748674241c8e80ffc348`.
Keep the entire 68-entry search/filter projection unchanged, including string
values and array order: `id`, `category`, `summary`, `triggers`, `antiTriggers`,
and `taskTypes`. Keep search code, normalization, weights and ties unchanged.
Preserve relations, specialization and maturity too. Restore both owner entrypoint
frontmatters to their canonical baseline `55f960847fa2a06a750a1a6e20c4e7f95ea10449`.
Only conditional body instructions, declared references and explicit selected
method-directory rows may change under this contract.

The three proposed method rows cover:

- Reading only new messages from an authorized running task with an exact saved
  position, bounded reads, atomic progress commits and honest drain uncertainty.
- Observing an already-authorized local process without inventing percentages,
  ETA, application success, or new launch/cancellation authority.
- Turning supplied mathematical prose into a source-linked specification draft,
  keeping missing units/domains and conflicting relations unresolved and requesting
  separate domain review; this is not source verification, solving or proof.

Start with the product README and select by the actual task and exclusions.
Read the complete owner and only its matching reference. The directory must be
usable from ordinary task descriptions without already knowing method titles.
Global lexical top-1 selection and native-host automatic selection are not promised
by this alternate interface. Unchanged lexical limitations remain limitations.

## Frozen acceptance conditions

Before adoption, a non-author reviewer must assess the exact complete candidate:
three title-free positive applications, the four Hermes adjacent-owner exclusions,
the three Math non-method exclusions, and two ordinary parent-workflow controls.
That is 12 caller requests, not 12 new test files. Retain all behavior, source,
authority, unknown/conflict, and domain-review requirements. A linked but
undiscoverable page fails this contract; do not force an exact-title lookup to pass.

Mechanically compare the full 68-entry search projection, both native discovery
frontmatters, and product-only build/validation. New directory rows initially state
`not-assessed-by-this-overlay`; only a fresh scoped independent receipt with exact
method path/hash bindings can justify `independently-document-reviewed`. After
bundling that receipt verbatim, separately review the final status/pointer delta.
Document review does not change a method's DRAFT status, establish source rights,
close R10 obligations, or qualify runtime/performance outcomes.

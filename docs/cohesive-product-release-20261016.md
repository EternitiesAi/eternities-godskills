# Cohesive Godskills release — October 16, 2026

This release deepens the existing portable product rather than making every
source record a new installed skill. It starts at `c4e0fd2` and retains the 93
skill IDs and 21 categories. The implementation is merged and pushed at
`253c55c00a80532d5a0fa5ec3ac5c946a3d98b9d`, and the exact content release is
installed with verified rollback bytes. Checked gates and exact identities follow.

## Useful changes

- Business and creative methods now include commercial-driver diagnosis,
  positioning-to-copy, art-direction-to-layout, core-loop playtesting, supplied
  audio editing/mixing, contrastive practice and meaning-preserving voice work.
- Selected source synthesis adds feasible creator slates, camera-driven asset
  refinement, assignment-based causal-design choices, telemetry-cardinality
  budgeting and reader-knowledge/reveal revision.
- Engineering, research, memory, long-horizon work and evaluation entrypoints
  emphasize usable outcomes, discriminating checks, matched task comparisons,
  scoped continuity and proportional process. They do not require a ledger,
  packet or delegation chain for every small action. Phoenix adds a conditional
  diagnostic-experiment method.
- Discovery distinguishes ordinary transformations from declined or quoted
  specialist actions. Runtime-scope admission no longer discards supported
  game/scene work merely because a narrow feature word is absent. Useful
  method-specific metadata exposes the new conditional methods.
- The front page and start map provide a short entry route. Existing release
  history is preserved under `docs/history/`, not discarded.

There are 13 new conditional references and 19 refined owner entrypoints, not
13 compulsory additional skills. They are opened only when the current job
needs them. The selected method directory separately binds document review to
exact method bytes; instruction review is not a performance certification.

## Scope and source accounting

Two author lanes inspected all 93 complete entrypoints: 37 business/creative/
human-facing and 56 technical/research/agent-facing. Reference reads are listed
separately and are not claimed exhaustive. Independent reviewers examined the
changed guidance and the discovery implementation. Retained entrypoints do not
inherit a new independent quality certification simply from being inventoried.

Six deduplicated lightweight public source snapshots were added to the canonical
warehouse. They contain 478 tracked files / 3,318,588 source bytes, approximately
5 MiB including Git metadata at acquisition. The index moved from 2,610 to 2,616
records with previous rows preserved; no existing checkout was refreshed. The
selected 13 new entrypoints, three additional references and reused comparisons
were material for five original methods. Of 102 newly indexed source
entrypoints, 89 remain indexed-only, not semantically refined or installed.
Sources and notices stay preserved; no acquired code was executed.

The historical quarry remains distinct: **49,514 open R10 obligations and 163
conflicts are not closed by this release**. No terminal source ledger mutation,
exhaustive Internet coverage or universal superiority claim is made.

The initial reviews found a recurring-revenue population ambiguity, missing
discovery cues, over-restrictive runtime eligibility and a missing adopted
source attribution. Repairs are versioned beside the original findings.
The initial routing attempt and its failing challenges are not relabeled as
successful. Full-suite checks also found historical version/projection assumptions
and a real browser-lifecycle admission loss. Historical fixtures remain exact;
named projections preserve current semantic and unrelated-field drift checks.
An independent follow-up found ordinary CSS form animation attracting the game
owner. The repair requires simulation or an explicit animation/render/frame loop
for that browser-lifecycle path. The failed review and failing regression remain.

The first canonical-checkout suite also recorded two failed Git source reads
from the external warehouse. Both declared pinned bodies subsequently matched
their original SHA-256 in direct checks (36 ms and 34 ms), without modifying
source, implementation or tests. The failure receipt is preserved; the transient
storage/process cause is not established conclusively. The unchanged full rerun
is recorded separately, not substituted for the original failed evidence.

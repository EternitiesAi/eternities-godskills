# Cognitive workflows for Godskills

Dom approved the previously described capability expansion and authorized two
GPT-6.1-Sol xhigh and two GPT-6-Luna max workers on October 3. This is a finite
upgrade to the universal product, not resumption of the acquired-source corpus,
the old heartbeat, or an indefinite autonomous runtime project.

## Product contract

Add six selectively discoverable methods with useful procedures and concrete
examples. Keep their entrypoints compact and their effects inside the receiving
host's existing authority. Use ordinary agent competence when a method does not
fit; do not impose these procedures on simple messages or routine edits.

| Entrypoint | Outcome | Owner |
| --- | --- | --- |
| voice-style-calibration | Infer an inspectable voice profile from authorized examples; apply it without changing facts or imitating an identity deceptively | Luna author A |
| imaginative-concept-development | Explore genuinely different concepts, develop promising directions and distinguish fictional invention from factual claims | Luna author A |
| interpersonal-understanding-and-dialogue | Separate observed statements from tentative interpretations, clarify needs and compose respectful dialogue without diagnosis or coercion | Luna author B |
| memory-retention-and-recovery | Preserve and retrieve minimal task-critical state; invalidate stale records and test continuity without claiming unlimited recall | Luna author B |
| completeness-and-consistency-audit | Map declared obligations to delivered artifacts, inspect omissions and contradictions and distinguish useful completeness from output length | Sol author C |
| long-horizon-work-continuity | Carry an authorized objective through milestones, interruption and resumption, reconciling uncertain effects before retry | Sol author C |

This is six methods, not six magical model capabilities. Psychological scope is
interpersonal judgment, not mental-health diagnosis, treatment, mind reading or
covert manipulation. Creative methods leave room for originality. Long-horizon
guidance does not implement a scheduler or imply an agent continues when no
runner is active. Memory requires an actual host-approved store and does not
alter Codex's memory permissions or Keel policy.

## Acceptance

1. All six bodies give actionable decision criteria, inputs, useful outputs,
   failure recovery and finish conditions; examples exercise nontrivial cases.
2. A different worker reviews each exact authored tree and applies the skills to
   independent raw fixtures without an expected-answer leak. Record outputs,
   concrete defects, limitations and any repairs; self-READY is not acceptance.
3. Discovery tests exercise the real catalog with direct, paraphrase and adjacent
   requests. Do not assert headings or claim lexical retrieval is semantic proof.
4. Existing product integrity, method-directory, export and installer checks pass.
   Repeat changed-surface checks, then one bounded full root suite before release.
5. Validate a fresh exported pack with no warehouse or provider dependency. Do
   not turn same-host extraction into cross-platform or fresh-OS qualification.
6. Reconcile current main before integration. Publish a verified product and
   install only with a fresh backup, exact manifests and unchanged unrelated
   skills. If concurrent edits appear, reconcile rather than overwrite.
7. Final report distinguishes instruction review, fixture applications, runtime
   demonstrations and unmeasured quality. Stop workers at the release checkpoint;
   leave the old automation paused.

## Worker layout

Three disjoint authors produce two methods each. The second Sol worker prepares
the independent evaluation protocol and hidden fixtures while parent implements
discovery checks and portable/native integration guidance. After drafts return,
workers are reused for non-author reviews and repairs. At most four workers are
active; no descendants or API-provider fallback is authorized.

## Model and retained contracts

The existing weighted terms, IDF calculation, token groups, exact-ID bonus,
filters, literal anti-trigger exclusions, score rounding, and score/ID tie sort
remain. A small additional lexical layer recognizes five intent families using
conjunctions of request cues:

| Intent family | Required request evidence | Required metadata evidence |
| --- | --- | --- |
| Written authorial voice | Authorial style plus text adaptation | Voice plus samples, registers, traits, or authorial guidance |
| Interpersonal clarification | Misunderstanding plus participants plus a dialogue action | Interpersonal/listening plus dialogue/conflict |
| Task-record recovery | Resumption plus a prior record plus freshness checking | Memory/continuity plus stale/freshness plus recovery |
| Delivery coverage and agreement | Obligation/gap plus artifact/delivery plus comparison | Obligations/requirements plus omissions plus consistency |
| Sustained work/effect reconciliation | Work horizon plus continued delivery plus interruption/effect state | Milestones plus resumption/interruption plus objective/project |

Profiles inspect only supplied catalog summaries and triggers. They contain no
skill-ID keys, complete-query lookup, metadata flooding, embeddings, model calls,
or external state. A renamed copy of the voice candidate still matches; an empty
catalog yields no candidates. Phrase normalization uses NFKC, lowercasing, and
letter/number word boundaries so casing, width, and punctuation can vary.

Matching request and metadata evidence adds a capped 60-point ordering bonus,
even if several profiles match a candidate. This is a heuristic, not a
probability, calibrated confidence, applicability verdict, or permission. Reasons
expose the lexical intent and cue groups separately from literal matched terms.
The output method is now `offline-lexical-intent-phrases-v2`.

For a corroborated written-voice request, `sound` is removed from the query's
weighted terms, preventing the old sound/audio/DSP group from manufacturing an
audio match. Explicit media/DSP vocabulary disables the written-voice and
interpersonal boosts, preserving the specialist's existing path. Other requests
retain the prior lexical path. Category/task filters and literal anti-triggers
run before intent scoring. Authority and activation stay `none`; related skills
and specialization remain descriptive only.

## Limits and parent integration gate

The profiles are finite English lexical rules. They do not infer arbitrary
paraphrases, general negation, quotation scope, hidden intent, or semantic
applicability. Existing anti-triggers remain literal substring exclusions. A
negated media term can still disable an intent boost. Requests with multiple
intents or catalogs with overlapping descriptions can remain ambiguous.
Existing incidental lexical candidates can still appear below the new owner;
for example, `without`, `out`, `whether`, or `not` still contribute to secondary
results. The bounded repair does not claim comprehensive relevance calibration.

The tracked catalog, index, and release manifests are deliberately unchanged.
Consequently `node product/bin/godskills.mjs validate` on this source worktree
currently exits 1 with `Release file set changed or undeclared files present`:
the release has not been regenerated to include the adjacent module and changed
search bytes. This is a real integration gate, not a passing release claim.
Temporary-pack rebuilds passed validation and CLI search/route tests. After
review, the parent must rebuild and verify the adopted pack and run its own
independent evaluation before treating this as an integrated release.

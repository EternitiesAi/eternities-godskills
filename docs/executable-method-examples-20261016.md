# Three executable Godskills applications

This milestone adds three optional, offline worked examples to the portable pack,
without adding entrypoint names or changing the reviewed instruction bodies.
The candidate keeps **93 skills, 21 categories and 29 selected methods**.

## What is useful now

- **Shared-capacity diagnosis:** `analyzeFlow` reconciles mixed classes against
  resource hours, keeps blocked work separate from ready demand, and counts
  separately supplied rework once. Its demo tests a prevented-rework scenario
  without claiming that clearing a local shortfall increases shipped output.
- **Onboarding cohorts:** `summarizeOnboarding` preserves eligible mature accounts
  in the denominator, separates pending and late acceptance, and computes a
  completer-only median without disguising missing or blocked outcomes. The caller
  must establish that acceptance means a useful result, not setup completion.
- **Animation interruptions:** `simulate` evaluates exclusive blend weights and
  authoritative event policy separately. Cancelled strikes and stale completions
  cannot act on the new playback instance. This is an event/weight model, not a
  rendered scene, networking layer or engine adapter.

See the [runnable guide](../product/examples/README.md) for commands and APIs.
No dependencies, provider credentials, repository warehouse or installation are
needed beyond Node.js 24+ to run these examples. Markdown-only skill use is unchanged.

## How they were checked

Three fresh GPT-6.1-Sol XHigh consumers authored separate examples using the named
shipped methods and a fixed input/output contract. A separate GPT-6-Astra High
reviewer froze 45 literal behavioral cases before reading their implementations.
Inherited host instructions remained present. The contract itself supplies many
domain requirements; success cannot be causally attributed to loading a skill.

The three author suites passed 166 tests. The first independent run passed 45/45.
The parent replayed those 45 cases against the actual exported copy and they passed.
The focused integration suite passed 208 tests with zero failures and one skipped
optional second-volume fixture. The exported pack ran validation, all three demos
and all three author suites from an unrelated working directory on Windows with
empty PATH and a minimal environment; all 368 manifest-bound files remained exact.
This is relocation, not filesystem access isolation. Independent code inspection
found only local or built-in imports in the examples.

The optional Linux/WSL invocation failed before yielding any verification result:
`Wsl/Service/CreateInstance/HCS_E_CONNECTION_TIMEOUT`. No current-release Linux
pass is claimed, and no shared host service was restarted to obtain one. Previous
release Linux results are historical, not evidence for this candidate.

Independent code/documentation review accepted all three examples at their exact
12-file identities, plus the three public documentation snapshots. The full
maintained suite passed **2,118 tests, zero failures, two skips** out of 2,120.
The skips were Windows symlink creation unavailable and the optional second-volume
fixture. Product and sampled test/evaluation inputs remained unchanged during it.

A separate review found gaps in the parent's packaging checks, not the example
implementations: partial change sampling, unbound candidate identity, an overstated
isolation interpretation, and a digest-shape-only test. The repaired checks compare
complete pack membership and manifest bytes, include protected activation inputs,
pin the accepted candidate through relocation and installation, and compare actual
digests. Isolation claims are narrowed. The prior findings remain preserved.
Only the parent portability test changed after the full run; its three strengthened
cases passed, and all other sampled input bytes remain identical. The full suite
was not redundantly rerun for that test-only change.

Separate packaging re-review found no remaining blocker in the four reported
findings: four clean controls passed and eleven negative probes were rejected for
their intended reasons. The final Windows relocated replay uses the repaired,
approved-release-bound verifier. Those generated probes are not an installation
simulation; actual delivery is recorded separately below.
